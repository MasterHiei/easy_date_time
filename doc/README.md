# Documentation map

Authored documentation is public, reviewed source. Generated reference output
is disposable and never part of a change set.

| Source | Audience | Owner | Publication rule |
|---|---|---|---|
| `README.md` | Package users | Maintainers | Stable task-oriented entry point |
| Public DartDoc in `lib/` | API users | API author + maintainer | Must match implementation and compile examples |
| `CONTEXT.md` | Contributors and agents | Maintainers | Shared domain glossary; no implementation detail |
| `doc/adr/` | Contributors and agents | Maintainers | Accepted, durable architectural decisions only |
| `AGENTS.md` | Contributors and agents | Maintainers | Root workflow and safety policy; add scoped files only for real local differences |
| `doc/agents/` | Contributors and agents | Maintainers | Repository-specific domain and issue-tracker guidance |
| `CONTRIBUTING.md` | Contributors | Maintainers | Contribution workflow and verification commands |
| `doc/migration/` | Upgrading users | Maintainers | Versioned guides; preserve published paths |
| `CHANGELOG.md` | Package users | Release maintainer | Release-scoped user-visible changes only |

## Authority

`AGENTS.md` owns workflow and permissions; this file owns documentation
classification and publication. `CONTEXT.md` owns domain terminology. The
implementation and its tests are the source of truth for behavior; README,
DartDoc, migration guides, and examples must match them.

Public documentation describes implemented behavior or accepted, durable
decisions. It does not publish task context, reserve future APIs, or override
another source's authority.

## Generated documents

`doc/api/` is generated by DartDoc and ignored by Git. Run `dart doc --dry-run
.` when public DartDoc changes; never edit or stage generated output. Coverage,
test reports, and other build artifacts are likewise not authored docs.

## Change protocol

1. Update the owning source and every public summary that promises the changed
   behavior.
2. Compile, run, or test changed code examples according to their scope. Copied
   code that fails is a defect.
3. Review explicit paths before staging:

   ```bash
   git status --short
   git diff --check
   git add -- <exact-path-1> <exact-path-2>
   git diff --cached --check
   git diff --cached
   ```
